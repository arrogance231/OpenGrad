# OpenPapers V1 QA Program — Full Test Suite + End-to-End Verification

## Problem (established by exploration)
The v1.0.0 claim "publicly usable, reliable search" is not yet evidence-backed:
- **7 of 37 MCP tools have zero tests** (get_bibtex, research_topic, resolve_author, read_paper, search_within_paper, find_repository_configs, vector_search) and 10 more are registration-only — ~46% of the public surface untested.
- **No test ever runs the real server process** — HTTP tests call `createHttpHandler().fetch()` in-process; stdio is untested; startup/shutdown/env config untested.
- **No live-provider evidence recorded** — the ranking metrics are offline-fixture; one thin smoke run exists; the repo's own docs admit live ranking is unmeasured.
- **Runtime gate is prose-only** — Docker compose smoke/benchmark/persistence are manual steps; SQLite default-path persistence across restart is untested E2E; GROBID is never exercised live.
- No test-level documentation, no coverage measurement, no shared test helpers (capture()/work() builders copy-pasted in ~10 files).

## Test levels (to be documented in `docs/testing.md`)
- **L0 Static** — tsc, architecture-check, tool-inventory (exists)
- **L1 Offline integration** — existing 62 files/217 tests + new matrix & helpers
- **L2 Process E2E offline** — NEW: spawned server over stdio + HTTP, 37/37 tool matrix, SQLite restart persistence
- **L3 Live network** — NEW: recorded provider reliability eval with acceptance thresholds (scheduled CI + manual)
- **L4 Runtime** — NEW: automated Docker E2E script (compose lifecycle, smoke, benchmark, persistence, GROBID)

## Work items

### 1. `docs/testing.md` (new)
Test-plan document: levels, what each proves, acceptance gates for 1.0, and a **claims matrix** mapping every public claim ("reliable search", "provenance preserved", "publicly usable") to its exact evidence file (test, eval result, or benchmark). Scoped per docs/limitations.md (e.g., exact-title live ranking is measured at Recall@10 with N=30, not guaranteed).

### 2. `tests/helpers.ts` (new shared infra)
`capture()` stub server, `work()`/`author()` builders, fake-provider factory (canonical works + throwing variants), seeded-DB builder, parsed-document factory. New suites use it; 2 worst-duplication files migrated.

### 3. `tests/tools-matrix.test.ts` (new) — close the 37-tool gap
Parametrized table-driven suite invoking ALL 37 tool handlers through the real registration boundary with fixture providers + in-memory DB; asserts JSON-schema-conformant shape + one key behavior per tool (incl. honest error paths: vector_search unconfigured, import_research_pack validation).

### 4. Fixture-provider mode (small src change)
`OPENPAPERS_FIXTURE_PROVIDERS=1` in `src/mcp/server.ts` startup swaps live adapters for the canonical offline fixture provider; documented in `docs/configuration.md` as offline/demo mode. Makes process E2E deterministic; also a user-facing feature.

### 5. `tests/e2e/stdio.e2e.test.ts` (new)
Spawn `node dist/mcp/server.js` (stdio, temp SQLite, fixture mode). Real MCP client handshake: initialize → tools/list = 37 → import_research_pack → get_paper round-trip → collections → export_research_pack → error paths (invalid tool/args) → graceful child-kill.

### 6. `tests/e2e/http.e2e.test.ts` (new)
Spawn server with `MCP_TRANSPORT=http` on a free port: real fetch over the socket, initialize/tools-list/call, JSON + SSE framing, session id handling, localhost origin validation rejection, SIGTERM → shutdown controller closes + port released.

### 7. `tests/e2e/sqlite-restart.test.ts` (new)
Ingest via fixture acquirer into `RESEARCH_DB_PATH` temp file → close → new service on same file → get_paper/FTS search/collections persist.

### 8. Live tier: dataset + runner + scripts
- `evals/datasets/live-search-v1.json` (~30 gold cases: 16 title-exact, 6 title-fuzzy, 8 identifier — drawn from the 23 canonical works).
- `evals/runners/run-live-search-reliability.mjs`: `service.search()` against real providers (default constructor), identity match via normalized arXiv/DOI, per-case rows + aggregate (liveRecall@10, identityCorrectRate, providerFailureTransparencyRate, zeroResultRate, latency), provenance headers per repo convention, ~1.1s throttle (≈35 polite requests).
- npm scripts: `eval:live-search`, `test:live` (adapter smoke + reliability runner).
- **Acceptance thresholds (1.0 claim):** title-exact Recall@10 ≥ 0.9, identity correctness ≥ 0.95, 100% of provider failures surfaced in transparency, zero fabricated identities. Miss → fix or scope the claim down; results committed either way.

### 9. `scripts/docker-e2e.mjs` + `test:docker`
One command: `compose up --build --wait` → adversarial smoke (37 tools) → benchmark (10 runs) → **persistence check** (create collection → restart container → collection survives) → GROBID alive + one live GROBID parse via a committed synthetic PDF fixture → `compose down -v`; writes `evals/results/docker-e2e-<commit12>.json`.

### 10. Storage + CI wiring
- Extend `scripts/postgres-integration.mjs` with a ResearchService-level round-trip (search + collections) on the CI Postgres.
- `vitest.config.ts`: coverage (v8, json+text), testTimeout 15s, include tests/e2e.
- `package.json`: `test:e2e`, `verify` = check + e2e (+ docker when available).
- `.github/workflows/ci.yml`: new `e2e` job (check + test:e2e); new `live-evals` job — weekly cron + workflow_dispatch running `test:live`, uploading result JSONs as artifacts (results committed by you when accepted).
